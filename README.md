# edu-by-mcp

Инструменты, с которыми ИИ-агент (Claude Code) может вести сайт учреждения образования в **конструкторе сайтов edu.by** (`wp.<регион>.edu.by/explorer.aspx`): разделы, страницы, новости, картинки, дизайн. Агент шлёт те же HTTP-запросы, что и веб-интерфейс конструктора, от имени вошедшего пользователя. Никаких скрытых API и обходов защиты.

Этот файл объясняет, что проект умеет, что он делает с сайтом, какие данные где лежат и куда уходит трафик.

## Что инструмент делает с сайтом

**Команды чтения** открывают страницы конструктора и переключают узлы дерева. Переключение узла – это POST-запрос, но он ничего не сохраняет: сервер только запоминает для сессии, какой раздел открыт.

**Команды записи** работают в два шага. Без флагов команда только читает и печатает план: что изменится (было → станет), предупреждения и короткий токен. С `--yes` план выполняется. Для удаления (`object trash`, `section delete`, `trash purge`) нужен `--token` из предпросмотра. Если сайт изменился после предпросмотра, токен не совпадёт, и команда откажется. После записи результат перечитывается с сайта.

**Записи.** Все изменения на живом сайте делались при исследовании, по прямому разрешению владельца:
- создан тестовый раздел «Тест загрузки картинок (удалить)», в него загружены картинки и пробные PDF;
- проверены публикация, корзина (удаление, восстановление, окончательное удаление) и экспорт дизайна в архив;
- тестовый раздел и все его объекты затем удалены, в том числе из корзины.

Дизайн, шаблоны, меню, права и чужие объекты не менялись.

**Правила для будущих команд записи** (закреплены в [`CLAUDE.md`](CLAUDE.md)):
- Сначала показать, что изменится, затем выполнить только после подтверждения (`--yes`, `--token` или согласие человека). Так устроены все команды записи.
- Публикация, удаление, перезапись, изменение меню и прав – только с явного согласия.
- Удаление из корзины – только по явно названным id. «Выделить всё» не используется никогда: в корзине лежат и чужие удалённые объекты.
- Шаблоны страниц из инструмента не сохраняются: даже сохранение без правок переписывает шаблон всего сайта.
- После записи результат перечитывается с сайта. Например, слишком большую картинку сервер отклоняет без сообщения об ошибке.
- Запросы идут по одному, с паузой. Параллельных массовых запросов нет.

## Вход и пароль

- Вход защищён **капчей**. Её всегда вводит человек: проект не пытается её решить, обойти или собрать. `./edu session login` открывает окно браузера с заполненными сайтом, логином и паролем из `.env`, а человек вводит только капчу.
- Пароль хранится открытым текстом в `.env` (исключён из git) и нигде не печатается.
- Сессия живёт около часа без активности. `./edu session keepalive` раз в 45 минут отправляет лёгкий запрос, чтобы она не истекла. Если сессия всё же истекла, команды не повторяют запрос, а просят войти заново.
- Cookie сессии лежат в `.session/cookies.json` (права 600). В выводе и логах от них видны только последние 4 символа.

## Какие данные хранятся локально

Всё ниже лежит в `.session/` и исключено из git.

| Путь | Содержимое |
|---|---|
| `cookies.json` | cookie сессии конструктора |
| `browser-profile/` | профиль встроенного Chromium |
| `har/*.raw.jsonl` | сырые записи трафика, в них есть cookie. Агент их не читает |
| `har/*.sanitized.*` | те же записи без cookie, токенов и идентификаторов сессии. С ними и работают |
| `tree-<сайт>.json` | номера, названия и пути разделов |
| `design/` | резервная копия дизайна, экспорт архива дизайна, прототип нового стиля |
| `explore/`, `probe/` | скриншоты, страницы и скрипты исследования. Логи маскируют идентификаторы сессии |

В git попадают только код, `knowledge/` (описания запросов без секретов, со выдуманными значениями в примерах) и тесты. Перед каждым коммитом diff проверяется на секреты.

## Куда идёт трафик

- **edu.by** (`edu.by` и `*.edu.by`) – только через настроенный прокси. Это ограничено в коде: httpx-клиент подключает прокси только для этих доменов, браузер получает PAC-файл с тем же правилом. Если прокси настроен, но не работает, запрос падает с ошибкой, а не идёт напрямую.
- **Всё остальное** – напрямую: сборка образа, пакеты, сторонние ресурсы в браузере. Прокси не выставляется на всю систему.
- **ИИ-агент.** Когда с проектом работает Claude Code, всё, что агент читает (содержимое страниц сайта, ответы конструктора, вывод команд), уходит в API Anthropic как часть диалога. Cookie, пароль и идентификаторы сессии в этот вывод не попадают: они маскируются.

## Быстрый старт

Нужны Docker и X-сервер (для окна входа). Всё запускается в контейнере: Python на хосте не нужен.

```bash
cp .env.example .env        # указать сайт, логин, пароль и способ выхода в сеть
./edu build                 # собрать образ (Playwright Chromium + пакет)
./edu proxy up              # поднять прокси (прямой режим или Shadowsocks)
./edu proxy check           # убедиться, что конструктор доступен
./edu session login         # окно браузера: ввести капчу и нажать «Войти»
./edu session check         # 0 – сессия жива, 2 – истекла
./edu tree --depth 2        # дерево разделов
./edu objects 1041          # объекты раздела
./edu object show 2283      # один объект: тип, раздел, статус, HTML, изменяемые поля
./edu object set 2283 --set name="Новое описание"   # только план изменения
./edu object set 2283 --set name="Новое описание" --yes   # выполнить
```

Прямой режим (`EDU_INTERFACE`) нужен, когда маршрут по умолчанию идёт через VPN, который не достаёт до сайта. Тогда трафик edu.by выходит через физический интерфейс: `wlo1` для Wi-Fi, `eno1` для кабеля. Подробности в `CLAUDE.md`, раздел Proxy.

Остальные команды: `./edu --help`, `./edu test`, `./edu lint`.

## Что известно о конструкторе

Всё в [`knowledge/`](knowledge/README.md) взято из реального трафика, у каждого файла указаны источник и степень проверки. Кратко о важном:
- **Картинки** загружаются до ~300 000 байт. Файл больше сервер отклоняет **без сообщения**: ответ 200, но картинки нет.
- **Документы (PDF, DOCX) сайт не хранит.** Объекты «Гиперссылка на файл для скачивания» – это карточки со ссылкой, например на Яндекс.Диск.
- **Корзина** отдельная для каждого типа объектов. Удаление раздела отправляет его объекты в корзину, а сам раздел исчезает. Из корзины объект можно восстановить в любой раздел или удалить навсегда.
- Каждое сохранение объекта отправляет **все поля**. Если не передать флажок «Разрешить публикацию», объект снимется с публикации.
- Дерево разделов подгружается лениво: один запрос на раздел, ответ около 110 KB. Поэтому пути к разделам кешируются.

## Структура

```
edu                     # обёртка: ./edu <команда> (docker compose)
src/edu_by/             # CLI и клиент: config, http, session, webforms, har, direct_proxy
src/edu_by/site.py      # Site: вход, клиент, дерево, кеш – общий для CLI и MCP
src/edu_by/api/         # чтение (explorer, objects, treecache) и запись по плану (changes, objects_write, sections, trash)
docs/mcp.md             # устройство будущего MCP-сервера
knowledge/              # проверенные факты о конструкторе (запросы, поля, особенности)
.claude/skills/         # инструкции для агентов
tests/                  # pytest на сохранённой разметке с выдуманными данными
TASKS.md                # план работ
CLAUDE.md               # правила для агента: безопасность, прокси, git, стиль
```
